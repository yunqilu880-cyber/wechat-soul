# 普通微信好友聊天的可行性核查（2026-10-30）

## 用户目标

别人通过微信号或个人二维码添加一个独立的**普通个人微信账号**，在普通好友私聊中与 DeepSeek 对话。这个目标与当前 iLink/ClawBot 授权机器人会话不同：项目的登录二维码是管理员授权码，不是供他人添加好友的二维码。

## 已核对的路径

| 路径 | 是否为普通微信好友 | 接入与维护情况 | 结论 |
| --- | --- | --- | --- |
| [腾讯 iLink/ClawBot](https://github.com/Tencent/openclaw-weixin/blob/main/README.zh_CN.md) | 否，属于授权的机器人会话 | 扫码登录、长轮询收发；当前 WeChatSoul 已接入兼容 SDK。关于无法按微信号添加及跨设备同步，见[上游问题报告](https://github.com/Tencent/openclaw-weixin/issues/167)，这是用户报告，非官方能力承诺。 | 保留为已有通道；不能宣传为普通好友。 |
| [Wechaty](https://github.com/wechaty/wechaty) | 取决于 Puppet，可使用个人号 | 框架本身不提供通用、稳定的个人微信登录能力；其 [Wechat4u Puppet](https://github.com/nodeWechat/wechaty-puppet-wechat4u) 明示 Web 微信登录限制。其他 Puppet 需要逐个核对服务、费用和账号支持。 | 不宜直接替换通道并声称可用。 |
| [WeChatFerry](https://github.com/lich0821/WeChatFerry) | 是，以登录的个人号收发 | Windows 微信客户端 Hook；原仓库于 2026-07-10 归档。其 Node [集成指南](https://github.com/wechatferry/wechatferry/blob/main/docs/guide.md) 要求精确客户端版本 `3.9.12.17`；与新版微信不通用。 | 技术上存在路线，但版本、账号及维护风险高；未经隔离环境和真实账号测试不能作为正式功能。 |
| Windows 界面自动化 | 是，以已登录的个人号收发 | [wxauto4 免费版](https://docs.wxauto.org/docs/install.html)的公开兼容上限为 `4.1.8.107`，不覆盖本机新版客户端。[小漓视觉版](https://github.com/wens6515/weixin-wechat-wxauto-ocr-xiaoli)声称已适配 `4.1.15.56`，使用截图与 OCR 收发；这是项目作者的报告，尚未在本机复现。视觉方案需要保持桌面会话和微信窗口可用，界面变化可能导致识别或定位失败。 | 当前最适合以专用账号做小范围真机试验的候选；先验证收发和目标核验，再考虑接入 WeChatSoul。 |
| 企业微信「客户联系」/微信客服 | 不是普通个人号好友 | 可提供微信内私聊入口，具体 API 能力、权限和展示形式需要按所选产品重新设计。 | 若可接受企业身份，可单独研究官方渠道。 |

## 本轮试验与结论

- 只读检查了本机安装信息。已安装版本与所查 Node WeChatFerry 指南要求的 `3.9.12.17` 不一致；**没有发现可据此确认兼容的精确组合**。本机具体版本不写入公开仓库。
- 没有启动旧客户端、注入微信进程、登录账号或扫描二维码，因此没有真实个人好友收发结果。
- 已有资料支持的结论是：普通好友形态有非官方实现路径，但在当前项目及本机环境中**尚未验证可行**。不能将“能编译 SDK”当成“能稳定登录并回复微信好友”。
- 2026-10-30 追加核查：发现与本机新版客户端版本匹配的视觉自动化候选，并已在临时目录获取其 MIT 许可源码；未把第三方源码或二进制并入项目，也未启动它的自动回复。离线依赖与检查结果、真实收发结果应分别记录。
- 离线检查：在临时 Python 3.12 虚拟环境安装候选项目 `c5073a6` 的固定版本依赖，运行其 `test_visual_backend.py`：101 项通过、1 项跳过。该测试使用模拟图像和窗口行为，不能证明本机微信能被正确读取或回复。

## 若继续试验

先在独立测试环境核对客户端与适配器的精确版本、许可证和维护状态，并用专用测试账号完成登录、添加好友、收消息、回复、重启恢复与异常处理。试验应从单个预先指定的好友开始，先只读确认会话标题和消息方向，再向该好友发送一条固定测试回复，核对目标、内容与去重；之后才连接 DeepSeek。测试结果应单独记录；未经实测不要接入默认启动流程。不要通过绕过风控、账号权限或强制降级来宣称可用。当前项目的聊天、记忆和安全模块可以保留，仅在渠道适配层选择已验证的实现。
